## 一、业务逻辑概述（钱与资产的流转）

### 1.1 钱的主线：开单 → 收银 → 流水 → 清分 → 分账

```
接诊/咨询成交
   │
   ▼
开单 billing（产生"订单"=费用单，普通订单/定金订单/积分兑换/商城/拼团/小程序核销/住院/处方订单）
   │  addBillingInit → addBilling(Valid) → （折扣/赠送超配 → approvalBilling 审批）
   ▼
收银 payment（产生"缴费单"=payment，可拆多笔支付方式）
   │  addBillingPaymentV2 / payFee / batchPayFee（批量）
   │  支付方式 = 实收（现金/微信/支付宝/POS/聚合扫码…）+ 非实收（虚拟金：储值、权益卡本金赠送金、定金、积分、卡券、充值赠送、自定义虚拟金）
   ▼
支付通道 aggregatePay（线上：微信/支付宝/银联/银行直连；POS：ehpos）→ 交易流水（请求流水号 customerSerialNo / 三方交易流水号）
   │
   ▼
财务流水 paymentFlow（流水单号、收入/支出、发票金额，手动+自动两类，paymentFlowConfig 类目）
   │
   ▼
清分 aggregateClear（选择收款主体，把若干订单打包成一个清分批次：待清分→清分中→已清分；退款侧：待清分退款/未清分退款）
   │
   ▼
分账结算 aggregateThirdPay + aggregateMerchantInfo（收单机构按结算周期结算：未分账→部分分账→成功/失败；品牌抽佣金额、延时分账开关、品牌服务费%）
```

【i18n:liquidation/billDetailList/chargeRecord/rebateSettlement】清分与分账全套中文状态、字段来自这三个 bundle；`billDetailList.k11` 明确「品牌抽佣金额」「品牌服务费（%）」「延时分账」，`k16` 说明启用延时分账后「收款门店需逐笔分账，收单机构下个结算周期才结算」。

### 1.2 订单的旁路操作（billing 域）

- **转项（转项目）**：`/v1/billing/addTransfer`，订单内项目转成其他项目，产生「转项记录」（转出项/转入项/转出价值/转入价值/**转项盈亏**：平衡/转亏/转盈）。补缴时「费用单开单人=转项申请人」。【i18n:billing key122-128、payment key45】
- **转赠（转客户）**：`/v1/billing/addDonation`，把项目转赠给另一客户，产生「转赠记录」（受赠客户/转赠价值/是否扣除赠送金），可撤销（撤销将作废赠送金金额和退款记录）。【i18n:billing key71-89】
- **退款**：`/v1/billing/addRefund` → 退款记录（billingRecord），可跨店（`approvalTransferOnCorss`/`approvalRefundEquityCardCorss`）。【i18n:billing key129-158】
- **退单（整单作废重开）**：`/v1/billingBackRecord/*`，退单类型含「退款退单/订单退单/转赠退单/退单且修正」；确认后退单将**作废原始订单、收费记录、退款费用单的退费记录**，并还原项目次数、释放抵扣。【i18n:billing key46-89】
- **复单标记（copyOrder/planBOrder）**：把历史订单标记为「复单」（客户复单/接待复单/订单复单三维度），支持「复单且修正」；`planBOrder/pageV2` 返回 `notCopyNum`（未复单数）+ `pageData`。系统可定时自动复单（接待记录复单配置）。【i18n:repeatOrderConfig】
- **手工单（manualbilling）**：`addDeposit`（手工定金）/`deposit`(PUT)/`treatment`(PUT)，超时 60s（`timeout:6e4`），用于脱离接诊流程的补录。【调用点】
- **极速收款（speedPay）**：先收款后开单——「收款单号/收款金额/收款状态(成功/待收/失败)/开单状态(已开单/待开单)/关联订单/关联费用单」。【i18n:chargeRecord key99-113】

### 1.3 资产账户体系（客户挂在 360 视图下的钱包）

| 资产 | 前端叫法 | 结构 | 管理模块 |
|---|---|---|---|
| balance | 储值/余额 | 本金 + 赠送（含限定赠送） | `/v1/balance*`、`balanceByHand`、`balanceTransfer` |
| deposit | 定金 | 专用款项，可抵扣/退款/退入储值 | `/v1/deposit*`、`/v2/deposit/*`、`manualbilling/addDeposit` |
| equityCard | 权益卡（抵扣金卡） | 本金 + 赠送金 + 消费折扣 + 赠送项 + 赠送积分/成长值 | `/v1/equityCard*`、`billingEquityCard*`、`equityVerify` |
| score / 积分 | 积分 | 可按最大百分比抵扣订单 | `/v1/score*`、`scoreClear`、`scoreCostBack` |
| 成长值 growth | 成长值 | 决定会员等级（scoreRange 区间） | `/v1/member/level/*`、`memberlevelmorecondition` |
| goldCoin | 金币 | 可兑换积分 | `memberInterests` 配置 `{{goldCoinAlias}}兑换积分配置` |
| 卡券 cardCoupon | 代金券/折扣券/体验券 | 状态机：未使用→已使用/已过期/已作废/已赠送/已核销 | `/v1/scrm/card*`、`cardPutWay`、`cardPackage` |
| 项目余次 | 次卡/套餐余次 | 剩余次数、有效期 | `remainingAssets`、`/v1/project/getNumberOfProjectsDue` |
| asset | 固定资产（院内实物资产） | 类型树 + 编码 | `/v1/asset*`、`assetType` |

「储值余额、权益卡本金、定金余额」三者与赠送金分开统计：「仅查询客户可用储值余额、权益卡本金余额、定金余额总计金额，不包括赠送金额」。【i18n:346992(基础配置) key1006-1008】

### 1.4 会员体系（hc = HCustomer）

- **等级**：成长值区间（startScoreRange/endScoreRange）划分等级，本项目实测有「普卡(0~9999)、黑金卡(100000~∞)」等，挂在项目/套餐的 `allowedMemberLevels` 上决定可购性。【实测 /v1/billing/getBillingProjectList】
- **会员卡（hc-member-card）**：卡系(card-series)→卡项(card-item)→品项权益/尊享服务(service)/亲友礼包(gift-right)；会员卡分**储值型/消费型**；升卡方式=自动升卡/手动确认；生命周期=开卡→续卡→升卡→退卡。【i18n:chMemberShip】
- **权益（member/equity）**：积分回馈率、支付折扣、生日礼物、免费接送/泊车等，服务方式=系统自动核销/商家线下服务。【i18n:memberInterests】
- **任务（积分/成长值获取）**：新人任务/日常任务/个人任务，结算时机=缴费时/划扣时/消费时（订单支付完成时、实际消费时、对应划扣时）。【i18n:memberInterests key240-325】

## 二、核心实体与数据模型（含实测字段）

### 2.1 订单 / 收费单 billing

- 主键 `id`；列表查询 `/v1/billing/billingListV2`（POST body），过滤字段（调用点还原）：`customerSureType, depositNo, customerId, status, deductStatus, refundToType, refundFlag, startCreateDate, endCreateDate, startDeductTime, endDeductTime, startRefundTime, endRefundTime, dataSource, startSubDepositAmount, endSubDepositAmount, depositItemIds, exportTitle, modularKey`。【调用点】
- 列表列（i18n:billing）：订单号/订单类型/订单总价/实收/**欠费**/订单状态(**清讫**)/订单来源/订单审批状态(待审批、审批中、已通过、已拒绝、**滞后拒绝**)/欠费审批状态/是否退费/是否转项/是否转赠/收货方式(到店自提、快递到家)/订单开单人/协助开单人/开单时间/门诊订单|住院订单。
- 项目/套餐可售清单：`POST /v1/billing/getBillingProjectList` → `{total, projects[]}`，`POST /v1/billing/getBillingPackageList` → `{packages[], total}`；单条记录含 `allowedMemberLevels[{id, memberLevelName, startScoreRange, endScoreRange, tenantId}]`、`ableChooseCount`、`ableGiftCount`、`ableDiscountFlag`。【实测】
- 类型树：`GET /v1/billing/allType` → `{projectType:[{id,title,children[]}], packageType:[...]}`（本项目有「北科类→细胞储存 Cell storage」等类目）。【实测】
- 项目价格（按医生/科室）：`POST /v1/projectMarket/getProjectMarketByPidAndDids` → `Array(65) of {billTotalPrice, price, oneManualPrice, manualPriceType, defaultCount, doctorInfo:'{"name":"常规售价"}', lowestOrderPrice, projectId, departmentInfo...}`。【实测】

### 2.2 缴费单 payment

- 列表 `/v1/payment/paymentListV2` / 详情 `paymentDetailsV2`；列（i18n:payment）：收银类型（收费/退费）、客户、**抵扣金**、**虚拟金**、收银状态（待处理/已处理/已作废/挂起）、收费时间、**实际入账日期**、应收/应退、实收/实退、费用单号、已开收据、已开发票。
- 收银初始化：`addBillingPaymentInit(billingId)`、`batchPayFeeInit(customerId, paymentIds, saleItemIdList, operationSourceType, billingId)`、`refundPayFeeInit`。【调用点】
- 判重/幂等：`getDupPayment(id, mark)`、`getDupPayment2`、`judgePaymentResubmit`。【调用点】
- 作废：`PUT /v1/payment/cancel`（paymentCancel）；改支付方式 `updatePayWay`；改医生科室 `updateDoctorOrDept`；打印时间 `updateLastPrintTime(id, mark)`。

### 2.3 支付流水 / 财务流水

- paymentFlow（业务支付流水）：`paymentFlowNo, incomeFlag(类型), paymentFlowConfigName(具体类目), payMoney, operatorName(财务), invoiceMoney(开具发票), paymentInfo(业务发生单号), departmentName, customerPhone, dataType(手动/自动)`。【i18n:flowingList】
- 聚合交易（chargeRecord·线上支付明细）：`交易订单号/业务订单号/原业务订单号/交易时间/终端号/交易类型/支付方式/支付状态/撤销状态/三方交易流水号`。交易状态枚举：`success 支付成功, faild 支付失败, pending 支付中, refunding 退款中, refundSuccess 退款成功, refundFaild 退款失败, partRefund 部分退款, hasRefund 已退款`；支付通道形态 `code 二维码收款 / pos POS机收款`；payMode：`wechat 微信, alipay 支付宝, debitCard 借记卡, creditCard 贷记卡, unionDebitCard 银联二维码借记, unionCreditCard 银联二维码贷记`。【i18n:chargeRecord】

### 2.4 清分 / 分账

- 清分批次（aggregateClear）：`batchNo 清分批次号, initiationTime, initiator, confirmer, confirmTime, number 交易笔数, amount 交易总额, confirmStatus(待确认/已确认/已作废), liquidationStatus(成功/失败/部分成功)`；订单侧 `accountStatus 分账状态, payMode, serialNo 交易流水号`。清分订单状态：待清分/清分中/已清分/待清分退款/未清分退款。【i18n:liquidation】
- 商户（aggregateMerchantInfo）：`商户简称/企业名称/主体类型/延时分账/品牌服务费（%）`；实测 `POST /v1/aggregateMerchantInfo` 缺参会报「品牌服务费不能为空,是否开启延时分账不能为空,唯一标识不能为空」→ 字段名可从报错反推。【实测】

### 2.5 储值 / 余额 balance

- 充值：`balanceRecharge`（transBalanceRecharge 转充值）、充值赠送配置 `sysBasicRechargeGift/getConfig|saveConfig`；充值单状态：未付款/已付款/已作废/欠费；`cancelRecharge`（GET，invalidRecharge(id)）作废。【调用点】
- 退款：`balanceRefund`（参数含 `crossFlag, customerId, scoreFlag, ...`）、`balanceRefundInit(customerId)`、审批 `approvalRecharge/approvalRefund`、`cancelRefund`。【调用点】
- 手工调整 balanceByHand：`balanceRechargeByHand / balanceRefundByHand / updateBalanceRechargeByHand / deleteBalanceRechargeByHand(id)`。【调用点】
- 跨店划拨 balanceTransfer：`addBalanceTransfer / approvalTransfer / approvalTransferOnCorss(跨店审批) / balanceTransferList(current,size,sort,...) / cancelTransfer(id)`。【调用点】
- 列表三张：`allBalanceRechargeList(index,size,crossFlag,startTime,endTime,customerId,descFlag,getTotalFlag)`、`allBalanceRefundList`、`allBalanceDeductionList`（抵扣流水）。【调用点】
- 保有量报表：`/report/v1/payment/depositAndBalanceTenure`（定金+储值保有）。

### 2.6 定金 deposit

- 单据字段（i18n:deposit.form）：定金单号/收款状态(未付款、已付款、已作废、欠费)/**可抵扣金额**/退款状态(已退、未退)/退款去向(**退款到费用单**、账户、**退入储值(专项)**)/确认状态(未确认、待确认、已确认)/定金类型(门诊订单、住院订单)/明细来源(开单、转项退入、退款退入、抵扣、退款)。
- 列表：`GET /v2/deposit/depositList`、统计 `depositListStatistics`、抵扣明细 `depositDeductList`、定金可抵项目/套餐 `getDepositProjectPage`/`getDepositPackagePage`【实测 均 10000，本租户返回 `[]`】。
- 退款：`/v2/deposit/refundDeposit` + `refundDepositApproval` + `getApprovalSettingOnRefund`（是否强制审批：`getDepositIsForceApproval`）；作废约束：仅「收款状态=未付款」可作废；退款记录作废约束：强制审批且非已作废、或非待处理均不可。【i18n:deposit.btnDisabledKeys】

### 2.7 权益卡 equityCard

- 模板定义（i18n:equityCardGroup）：本金/赠送（比例）、**本金适用范围与赠送金适用范围**（所有项目/套餐/商品/年卡/次卡 各自勾选）、抵扣规则（**不限制 / 优先使用本金 / 按比例抵扣**，比例=本金消耗:赠送金消耗）、消费折扣（范围+折数，金额耗尽或过期后失效）、赠送项/卡券/额外赠送积分成长值、**停用/退款扣除赠送积分公式 = (剩余本金/购买本金)×购买时赠送积分**、可购买会员等级、售卖时间、有效期（无限期/交费后N天生效+有效期N天）。
- 客户持有实例（i18n:billing/billingEquityCard）：权益卡号、本金、赠送金额/剩余赠送金额、状态（使用中/已作废/已过期；可用/已失效）；实例操作：延期 `addDeferApply/approvalDeferApply`、停用 `disabledEquityCard/equityCardDisabledConfirm/approvalDisabledEquityCard`、转到昔阳 `equityCardgoXy/approvalEquityCardgoXy`、退款 `billingEquityCardDetail/refundEquityCard(+Approval/Corss)`、流水 `rechargeRecordList/deductRecordList/refundRecordList`。
- 实测：`GET /v1/equityCard/get-select-equity-card` 返回 **27 种权益卡**，单条含 `label:"【抖音专属限购一张】99抵199"、isEnable、maxNumber、number、price、projectFlag、projectShowName、displayFlag、order` 等（限购、适用项目等语义字段）。【实测】

### 2.8 次卡 / 年卡 / 体验卡 / 套餐

- timecard（次卡）：`add/changeStatus/detail/getPage(name, cardTypeIdList, limit)/issuingInfo`；年卡 annualCard 同构。卡类型树 `timecardtype/tree`、`annualCardType/tree`。【调用点】
- 体验卡 experienceCard：项目组合「几选几」、对同一客户累计可认购次数、认购后有效期、上架状态（全部上架/部分上架/下架/待上架）、**认购撤回**、体验卡开单/转赠/退款。`GET /v1/experienceCard/getExperienceCardTypeOnBilling` → `{typeTree:[]}`【实测】。
- 套餐 package：`getByPage(name, packageTypeIds, limit, page)` → `{total, canEditTotal, packageRes[], select}`；字段同收费项目（ableChooseCount 等）；`getNumberOfPackageDue`（临期数量）。【实测/调用点】
- 卡券包 cardPackage + 投放 cardPutWay：`addCardPackage(id, packageName, packagePhoto, qrcodeId, cardPutIds)`、`addPutWay(activeName, batchIdList, detailList, receiveAndVerify)`、投放渠道=小程序/公众号二维码。【调用点】

### 2.9 会员卡（hc）与等级

- 卡系树：`POST /v1/hc-member-card/get-card-series-tree`、卡项 `get-card-item/get-card-item-list`、服务 `get-service(-page)`、礼包 `get-gift-right-page`、最低等级 `get-lowest-card-item`。【调用点】
- 订单：`hcMemberCardOrder/orderList/orderDetails/addOrUpdateOrder/cancelOrder/donateFriendsGift/cancelDonate/getFriendsGiftList/getMemberLevel/getServiceList/getUpgradeLogsList`；充值记录列=充值单号/订单类型/充值金额/付款/欠费。【i18n:chMemberShip key242-266】
- 退卡 hcMemberCardRefund：`initRefund/addRefund/cancelRefund/refundDetails/refundList`；退卡记录=退卡卡项/账户扣减金额/实退金额/未赠数量/已赠数量；校验「账户扣减金额不能大于当前预存款」「账户实退金额不能大于账户扣减金额」。【i18n:chMemberShip key203-298】
- 等级：`/v1/member/level/page|addLevel|update|delLevel|flushCurrent|flushNextLevel|getScoreRange|getHCustomerMemberLevel(实测 10002 空)`；升级条件=累计消费次数/累计消费金额/一次性充值/剩余储值/剩余项目…满足全部或任意；保级有效期、降级规则（逐级降）。【i18n:memberInterests key343-457】
- 升卡累计口径（i18n:chMemberShip）：可选「仅品项类订单结算金额/充值结算金额/订单结算金额/项目实收金额（含预收款抵扣和实收）」，退款是否影响累计升卡可配，且「退储值不会影响累计升卡金额」可切换。

### 2.10 积分 / 金币 / 资产变更

- score：角色 `getRoleList/getScoreRoleList/scoreRoleAddOrUpdate`、明细 `scoreContentList/scoreContentInfo/scoreContentExport`、同步 `synchronizeScore`。
- 清零：`scoreClear/expireScore(customerId)`（可清零积分查询）；规则（i18n:memberInterests）：不清零/自定义清零时间（清空上一自然年及之前积分）、**积分一次性抵扣订单金额最大百分比**、退款退/不退积分（按退款比例扣除）。
- scoreCostBack：积分消费返还规则 `addOrUpdate(range, type, levels)`。【调用点】

## 三、业务流程与状态机

### 3.1 收费流程（含审批门）

```
选客户(必须已到院：未到院客户不可开单 i18n:billing key81)
  → /v2/billing/addBillingInit(billingUserId)   拿折扣/审批配置
  → /v2/billing/addBilling(addSubmitParam)      或 addBillingValid 预校验
      折扣约束: billingDiscountSetting 按开单人配「默认折扣力度/最小开单折扣」，
      超出需审批（"开启则开单时需要按配置的折扣力度进行优惠,若超出配置力度,需审批通过后订单生效"）【i18n:billingDiscountConfig】
  → (需审批) /v2/billing/approvalBilling        订单审批状态: 待审批→审批中→已通过/已拒绝/滞后拒绝
  → /v1/payment/addBillingPaymentInit(billingId) → payFee / addBillingPaymentV2 / batchPayFee
      支付方式: 实收(payWay) + 非实收(virtualPayWay=虚拟金列表 getVirtualPayWayList)
      权益卡: billingEquityCard 按比例抵扣卡单独分类选择; getValidCardWithCustomerList / getValidCardListByPaymentId
  → 支付流水 paymentFlow / 聚合支付 aggregatePay (线上)
  → 打印/发票: billingInvoiceUsageInfo(add/batchAdd/cancel/judgeInvoiceNoUnique/getPrintInvoiceInit)
```

订单状态主轴：**未付款 → (部分付款) → 已付款/欠费 → 清讫**；旁轴：退款/转项/转赠各自「未/已」+ 审批状态。欠费需「确认欠费」（欠费审批状态），`/v2/billing/getBillingIsOwe(id)` 判单。缴费单状态：待处理/已处理/已作废/挂起。

### 3.2 退款 / 退单流程

```
退款(部分/按项):  /v1/payment/refundPayFeeInit → addRefund(billing.addRefund)
                  审批: billingRecord/getApprovalSettingOnRefund(customerId,autoFlag)
                        → billingRecordApproval(id, mark, reason)   跨店: approvalTransferOnCorss / crossHospitalRefund
                  撤销: cancelBillingRecord(billingRecordId, reason)
                  退款落账: 原路退回(1~3个工作日) 或 退到储值/费用单【i18n:chargeRecord.refund】
退单(整单):       /v1/billingBackRecord/addValid(id, mark) → addRecord(billBackTarget, billBackType, oldBillingId, oldBillingRecordId)
                  → confirmRecord(确认) / cancelRecord(作废) / updateRecord / recordList / recordDetails
                  退单类型: 退款退单 / 订单退单 / 转赠退单 / 退单且修正
                  状态: 待退单 → 已退单 / 已作废 / 挂起
                  连锁反应: 作废原始订单+收费记录+退款记录；还原项目次数；释放抵扣；回退返利【i18n:billing key49-78】
```

### 3.3 聚合支付与对账流程

```
getPayWays(可用支付方式) → pay(onlinePay: saveOrUpdate/billingSource...) 
  → queryTradeResult(轮询) → 成功: 入账 / 失败: chinaBankCloseOrder|close(customerSerialNo) 关单
异常: aggregatePayException/page + exceptionRefund + getExceptionRefundFlag
POS: updateEhposPay(queryType, customerSerialNo, tradeSerialNo, payStatus)
退款: refund(customerSerialNo) / aggregateThirdPay/queryDirectRefundInfo + refund(原路)
撤销: 撤销中 → 已撤销 / 已转入（"撤销该笔N元的支付并原路退还客户的支付账户"）
对账: 收银记录(实收支付方式/非实收支付方式/收费总数/退费总数/收费总额/退费总额/结余)
清分: 选收款主体→添加待清分订单(已加入批次不可重复选)→发起清分→确认清分(待确认→已确认)
分账: 未分账→部分分账→成功/失败；结算金额=支付金额-品牌抽佣金额；分账金额按主体结算比例拆分
```

### 3.4 业绩归属与提成

- 双开单人：订单开单人 + 协助开单人；特殊规则「**转项补缴为转项申请人，其他业务操作为原订单开单人**」。【i18n:payment key45】
- 业绩口径按虚拟金类型配置：`billingDiscountSetting.virtualGoldConfig` 中每类虚拟金（充值赠送/积分/卡券/权益卡赠送金/自定义）可配「是否参与业绩统计」「虚拟金支付抵扣退返」；自定义虚拟金开启退返后「退款时将抵扣部分计入退款结算的业绩中，但因没有账户概念，实际不会退返至账户」。【i18n:billingDiscountConfig】
- 折扣审批链：开单人折扣配置 + 审批人结束审批控制（审批人自身折扣不够时不能结束审批）。【i18n:billingDiscountConfig】
- 卡券业绩：`cardperformanceconfig/update`、`cardperformancelog/getList`（卡券赠送的业绩归属）。
- 业绩标签：`billingSmartLabel/getAllPerformanceLabelFromBilling`、`updateLabel(billingId, billingRecordId, labelList)`。【调用点】

### 3.5 储值赠送 / 充值赠送

- 配置 `sysBasicRechargeGift/getConfig|saveConfig`；「开启充值赠送强制审批开关后，触发审批的条件取决于基础配置-充值赠送审批配置」。【i18n:429479】
- 赠送金区分「普通/限定」（限定赠送余额 limitGivenBalance 只能用于指定范围）；退款时「是否扣除赠送金」可选（billing.json key249）。

### 3.6 会员等级升降 / 升卡

- 升级：成长值区间→等级；成长值获取=有效消费(实收)、定金抵扣、每日赠送、首单奖励（首单退款规则：不再/继续享受首单奖励；再次下单是否还算首单）。
- 降级：连续 N 天未登录 / N 天未获得 X 点成长值 → 逐级降级（不跨级）。
- 保级：成为会员起算，条件=累计消费次数/累计消费金额（并且/或），保级有效期。
- 积分回馈率按「升级前/升级后/当前等级」三种算法；黑名单（积分/成长值赠送黑名单，与返利配置互不影响）。【i18n:memberInterests】

## 五、Agent 可实现的运营场景

以下场景全部由上表接口组合而成，均为只读优先（先查后写，写操作需谨慎确认）。

1. **今日营收汇总**：`/report/v1/payment/billingCashiering`（收费/退费总额、实收/非实收、结余）+ `/report/v1/payment/billingCashieringPayWay`（按支付方式拆分）+ `/v1/paymentFlow/paymentFlowStatistics`（财务流水总收入/总支出/今日收入/今日支出）。【i18n:chargeRecord key133-158】
2. **欠费客户清单**：`/v2/billing/getBillingIsOwe` 逐单校验，或 `/v1/billing/billingListV2` 按状态过滤；客户维度欠费金额在客户 360（`memberCenter.customer.listConfig key62 欠费金额`、key63 欠费记录）。报表侧有 orderArrears（欠费人数/欠费总额/欠费合计）。
3. **会员卡到期提醒**：权益卡到期提醒配置 `/v1/equityCardExpirationReminderConfig/getConfig` + 客户权益卡 `/v1/billingEquityCard/list`（过滤有效期）；会员有效期在 `hcMemberCardOrder/getMemberLevel`、`/v1/member/level/getHCustomerMemberLevel`【实测本租户空】；卡券临期提醒（提前 N 天 10:00 发送，提醒发送人和所属咨询师）。【i18n:cardCouponMgt operation key20-28】
4. **储值余额分布**：`/report/v1/payment/depositAndBalanceTenure`（定金+储值保有）+ `/v1/remainingAssets/getNormalAssetsInfo`（账户金额/赠送金额/限定）+ `/v1/balance/balanceRechargeStatistics`（充值汇总）。注意「总额不包括赠送金额」口径。
5. **权益卡资产盘点**：`/v1/equityCard/get-select-equity-card`【实测 27 种模板】+ `/v1/billingEquityCard/list` 实例 + `deductRecordList/rechargeRecordList/refundRecordList` 流水 → 每种卡的本金/赠送金消耗率与折扣使用情况。
6. **退款与退单监控**：`/v1/billingRecord/billingRecordList`（退款状态：待审批/审批中/已通过/已拒绝/滞后拒绝）+ `/v1/billingBackRecord/recordList`（退单：待退单/已退单/已作废/挂起）+ `/v1/aggregatePayException/page`（支付异常）→ 异常单预警（如「滞后拒绝」堆积）。
7. **清分/分账对账**：`/v1/aggregateClear/page`（待清分/清分中/已清分/待清分退款/未清分退款）+ `/v1/aggregateThirdPay/settlePage` + `/v1/aggregateMerchantInfo/settleStatistics`（品牌抽佣、分账金额、结算余额门店）。
8. **复单分析（复购）**：`/v1/planBOrder/pageV2`（notCopyNum=未复单数）+ `/v1/multiple/orders/pageV2` → 复单率、待复单订单池。
9. **套餐/次卡余量与临期**：`/v1/package/getNumberOfPackageDue`、`/v1/project/getNumberOfProjectsDue` + `/v1/remainingAssets/getProjectAssetsInfo`（剩余/总数、剩余有效总价/剩余过期总价）。
10. **积分即将清零名单**：规则（清零时间月/日，实测租户日志可见「清空积分时间（月）新增【3】（日）【1】」）+ `/v1/scoreClear/expireScore(customerId)` 逐客户可清零积分。【实测 memberinterestslog】
11. **业绩核对**：`/v1/billingSmartLabel/getAllPerformanceLabelFromBilling` + 虚拟金业绩开关配置（billingDiscountSetting）→ 核对开单人/协助开单人业绩口径；返利执行 `/v1/rebates/excute/page` 待执行清单。
12. **加工件（口腔）结算提醒**：`/v1/machinedPartsBilling/overdueRemindPage` + 厂商对账单（未结算清单）。

## 六、二开注意事项与坑

1. **金额单位是元**（非分）；空值序列化成字符串 `"null"`/`"[]"`，判空必须做字符串比较；布尔也常以 `"0"/"1"` 字符串出现（如 `exemptionStr:"是"` 与 `exemptionFlag` 并存）。【实测 /v1/project/getInfo】
2. **分页两套参数**：`{page,limit}` 与 `{current,size}`（还有 `index,size`），同一接口混用会报 20002。从调用点看：balance/asset/hcMemberCard 用 `current/size` 或 `index/size`，package/annualCard/timecard 用 `page,limit`，需逐接口确认。`getTotalFlag`（是否返回总数）是高频附加参数，缺失会报 20001「是否获取总页数，不能为空」（见 equityCard/list）。【实测+调用点】
3. **HTTP 方法不能靠猜**：probe 用统一方法探测时大量 20002「Request method 'POST' not supported」——同一 controller 里 GET/POST/PUT 混用（如 `payment/cancel` 是 PUT、`payment/cancelRecharge` 是 GET）。写操作前先用允许的方法小参试。
4. **收银防重**：`judgePaymentResubmit`、`getDupPayment/getDupPayment2(id, mark)` 存在说明**重复提交校验前置**；二开自动化收银必须先判重，否则会产生重复缴费单。极速收款（speedPay）是「先收款后开单」，漏单风险点。
5. **退款不可逆且多路径**：线上支付原路退回（1~3 个工作日），储值/权益卡/定金退款各有独立审批（`getApprovalSettingOnRefund`、`getDepositIsForceApproval`、`aggregateRefundConfig`）；「滞后拒绝」状态表明审批可异步否决。退款业绩回退、返利回退、成长值/积分按比例扣除都是联动副作用。
6. **退单（billingBackRecord）是复合事务**：作废原始订单+收费记录+退款记录+还原次数+释放抵扣+回退返利/转赠；确认前必须 `addValid` 校验。直接改库级二开极易漏副作用。
7. **虚拟金没有账户概念**：自定义虚拟金退款只回业绩不回账户；「充值赠送/积分/卡券/权益卡赠送金」四类系统虚拟金各有独立账户与退返开关，参与业绩统计是按类型配置的。【i18n:billingDiscountConfig】
8. **权益卡抵扣规则三种模式**（不限制/优先本金/按比例）且本金与赠送金**适用范围独立**；按比例抵扣的卡在收银台是独立分类；停用/退款扣赠送积分公式=「(剩余本金/购买本金)×购买赠送积分」。二开计费必须完整复刻该公式。【i18n:equityCardGroup】
9. **定金作废仅限「未付款」**；已付款走退款+审批；「退入储值」是把定金转成储值（专项）——资金性质变更，审计上要留痕。
10. **清分批次不可重复合并订单**（「已经添加到本次清算中的订单不可选」），切换收款主体会清空已选；清分确认后状态不可逆，只能作废记录。
11. **多租户与跨店**：跨店退款/划拨/权益卡退款都有 `*Corss`（拼写如此）审批接口；集团下发数据（会员权益/卡系）在门店侧不可编辑，删除集团数据会级联删除下级门店。【i18n:memberInterests.btnDisabledKeys、equityCardGroup key152-154】
12. **鉴权与信封**：`Authorization: <裸JWT>`（无 Bearer）+ `lang: zh-CN`；成功码 10000/10001/10002 语义不同（操作成功/数据非空/数据为空），20001=业务参数缺失（报错即字段名提示，可用来反推参数）、20002=参数/方法错误、20004=缺必要请求参数、401=资源不存在。建议带 `X-No-Wrap: true` 拿原始 data。
13. **别名体系**：前端大量 `{{treatAlias}}`(治疗)、`{{equityCardName}}`(权益卡)、`{{repeatOrderName}}`(复单)、`{{goldCoinAlias}}`(金币)、`{{marketChannel}}` 是租户级可配置别名——二开展示文案不要写死「治疗/权益卡」。
14. **实测可用性**（本租户 bksw9854）：billing/allType、getBillingProjectList、getBillingPackageList、package/getByPage、project/getInfo、projectMarket/getProjectMarketByPidAndDids、equityCard/get-select-equity-card、multiple/orders/pageV2、planBOrder/pageV2、deposit/getDepositProjectPage、market/statistics/*、rebates/excute/page、memberinterestslog/getPage、aggregateMerchantInfo/merchantPage 等 20+ 只读接口可直接用；会员等级、权益卡实例、流水类在本租户为空（10002），接口本身可用。
