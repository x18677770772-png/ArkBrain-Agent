# 进销存 / 库存供应链域深度解析

> **证据来源**：`api-endpoints.json`（3973 个端点全量清单）、`probe-results.json`（508 个只读接口实测，其中进销存类 18 个可用）、
> `inventoryCockpit/cockpitData` 与 `inventory/getMaterialIdInventory` 实测返回（2026-09-23，租户 bksw9854）。
> 标注规则：**✅实测** = 已调用并返回成功；**待验证** = 依据端点命名推断，未实际调用。

## 一、业务逻辑概述

睿美云的进销存围绕**「物料/商品」**运转，服务的是医疗场景的耗材与商品：从**采购申请**到**采购单**，到**入库**进仓，
在治疗/收费环节被**领料核销**或**出库**消耗，辅以**盘点**、**关账对账**、**临期/低库存预警**，以及**委外加工件**的流转。

```
采购申请 purchaseApply ──审批──▶ 采购单 purchase ──关联──▶ 入库单 storage ──▶ 库存 inventory ↑
                                      │                            (linkStorage)          │
                                      ▼                                                  │
                                 采购记录 purchaseRecord ◀──关账 closeAccount             │
                                                                           领料核销       ▼
出库单 outInventory ◀──────────────────────────────────  verifyTakeMaterial / claimGoods
        │                                                        │
        └──────────── 退料 getRefundVerifyTake* ──────────────────┘

旁路：盘点 checkInventory（校正库存）｜加工件 machinedParts（委外生产/返工/逾期）
     寄存 materialConsignItem（供应商寄售）｜预警 materialWarn + 驾驶舱 inventoryCockpit
```

**与其它域的关系**：
- **治疗/收费域**：项目执行与收费时消耗物料，形成出库与划扣成本（报表域 `deductStatistics` 的实耗业绩与本域扣减相互印证）
- **收费/结算域**：采购关账（`purchaseRecord/closeAccount`）与日结、成本核算联动
- **渠道域**：`distribute/*` 是**渠道分账账户**（结算/银行卡/清分单），**不属于库存**，别混用

**运营中枢 — 库存驾驶舱（✅实测 `POST/GET /v1/inventoryCockpit/cockpitData`）**，19 个字段一次取全：

```json
{"abnormalConsumptionWarningNum":1,"accountScore":0,"costScore":25,
 "currentInventoryAmount":0,"highStockStockNum":0,"inventoryScore":22.96,
 "lowStockWarningNum":0,"nearExpirationWarningNum":4,"outOfStockWarningNum":0,
 "purchaseScore":0,"suggestMaterialList":[],"thisMonthPurchaseAmount":0,
 "todayCostProportion":0,"unsettledAmount":0,"waitApprovalPurchaseNum":0,
 "waitPurchaseApplyNum":0,"waitReceiptOrderNum":0,"waitReconciliationOrderNum":0}
```

字段含义：**四项评分**（inventoryScore 库存、costScore 成本、purchaseScore 采购、accountScore 台账）+
**四类预警**（低库存 / 高库存 / 缺货 / 临期）+ **四类待办**（待审批采购、待采购申请、待收货单、待对账单）+
**金额**（当前库存金额、本月采购额、未结算金额、今日成本占比）。实测本租户有 1 条异常消耗预警、4 条临期预警。

### 2.1 仓库 warehouse（12 接口，✅实测 3 个）

### 2.3 库存明细 inventory（20 接口，✅实测 `getMaterialIdInventory`）

`GET /api/v1/inventory/getMaterialIdInventory` → **53 条**库存记录，字段全集（66 个，实测）：

```
库存核心: inventory 库存数 | totalInventory 总库存 | numberOfWarehouses 覆盖仓数
         inventoryId | warehouseId | warehouseName | warehouseInventoryList(分仓) | inventoryList | inventoryAmountSum 金额

         effectiveDays 有效天数 | adventDay 临期天数 | adventFlag 临期标志 | canSaleDaysWarn 可售天数预警
数量预警: amountWarn 预警阈值(样例10) | amountWarnFlag | amountWarnList([{label:"卷",ratio,uId,value}])
         hightMaterial | isFilter2MonthData | status | statusText  ← 状态用 code+文案双字段
```

`getMaterialIdWarehouse`、`getWarehouseAndDepartment`。写接口 `delete` 危险，禁用。

## 三、业务流程与状态机

> ⚠️ 说明：以下状态流转**依据端点命名推断**（`approval`/`approvalNew`/`changeState`/`undo`/`invalid`/`finish`），
> 具体枚举值需调用带 `status/statusText` 的列表接口读取（库存明细已实测存在 `status`+`statusText` 双字段）——**待验证**。

### 3.1 采购 → 入库（主链路）

```
purchaseApply.add  ──▶ purchaseApply 待审批 ──PUT approval──▶ 已审批
        │ (linkApply)
        ▼
purchase.add ──POST approval──▶ 采购单 已审批 ──linkStorage──▶ storage.add 入库单
                                                                        │
                                          storage.approval / approvalNew（新审批流）
                                                                        ▼
                                              storage.changeState ──▶ 库存 inventory +N
                                                                        │
                                              undoStorage（撤销，回滚库存）
                                                                        ▼
                                   purchase.finish（完成）／ invalid（作废）
                                                                        ▼
                                   purchaseRecord ──▶ 关账 closeAccount（对账）
```

### 3.2 出库 / 领料 / 退还

```
outInventory.save ─▶ approval/approvalNew ─▶ changeState ─▶ 库存 -N ─▶ undoOutInventory（撤销）
verifyTakeMaterial.add ─▶ update（审核） ─▶ 核销出库 ─▶ updateVerifyTakeSend（发出）
                     └─▶ updateRefundVerifyTakeMaterial（退料）─▶ 库存回补
claimGoods（领用）──▶ takeNotUse 可回收 ──▶ 退回仓库
```

### 3.3 盘点：`checkInventory.add` → 生成差异 → 待验证是否走 `approval`。

### 3.4 关账对账（财务口）

`purchaseRecord.getCloseAccountAll`（关账列表）→ `EditCloseAccount`（编辑）→ `deleteCloseAccount`（删除）；
与驾驶舱 `waitReconciliationOrderNum`（待对账单数）、`unsettledAmount`（未结算金额）对应。

### 3.5 预警规则（可直接算给运营听）

## 五、Agent 可实现的运营场景

1. **库存日报**：一次 `cockpitData` 拿到四评分 + 四预警 + 四待办 + 三金额 → 直接生成日报卡片
2. **临期与低库存清单**：`getMaterialIdInventory` 过滤 `adventFlag/amountWarnFlag` → 生成「本周临期 4 项，异常消耗 1 项」清单并@仓管
3. **待办四单催办**：`waitApprovalPurchaseNum / waitPurchaseApplyNum / waitReceiptOrderNum / waitReconciliationOrderNum` 非零即推送提醒
4. **采购支出分析**：按 `purchaseRecord`（supplier/manufacturer 维度）+ 驾驶舱 `thisMonthPurchaseAmount` 出月度采购报表
5. **「领了没用」回收**：`inventory` 中 `takeNotUse > 0` 的物料 → 生成退库建议（直接对应成本回收）
6. **未结算/待对账**：`unsettledAmount` + `waitReconciliationOrderNum` → 财务周报
7. **加工件逾期**：`overdueRemindPage` + `reworkReasonPage` → 生产跟进清单
8. **出库成本**：`outInventory/getPriceSum`（含税/不含税）→ 对接成本核算

## 六、二开注意事项与坑

1. **字段类型坑（必读）**：与 §5.0 相同——金额/数量是**字符串**（`allFloatsAreStrings`，用 `FloatUtils.parseFloat`）、
   ID 是**字符串**（`allIdsAreString`，`parseLong`）、时间是**毫秒时间戳**。库存数字 `inventory:"3"` 别当数字比较大小。
2. **状态靠 `status`+`statusText` 双字段**：直接用 `statusText` 显示，别自己映射枚举。
3. **写操作高危**：`inventory/delete`、`storage/undoStorage`、`outInventory/undoOutInventory`、`purchaseRecord/deleteCloseAccount`
   会回滚真实库存与账目——**必须人工确认 + 幂等检查**，绝不让 Agent 直接调用。
4. **审批双版本**：`approval` 与 `approvalNew` 并存（新旧审批流），`PUT /v1/purchaseApply/approval` 方法是 **PUT** 不是 POST
   ——方法不匹配会报 `20002 您不是最新版本…Request method not supported`。
5. **多租户字段**：`defaultPreCrossTenant`、`tenantName`、`crossPre`（`getMaterialListByCrossPre`）说明支持**跨租户/集团仓**，
   做集团级分析时注意 `hospitalKey` + `tenantId` 双维度。
6. **导出接口**：`export`/`exportUtil`/`detailExport`/`batchPrint` 会生成文件任务（走 `/v1/exportlog/page` 异步下载），
   批量导出前确认权限与数据量。
7. **本租户数据稀疏**：实测驾驶舱多数金额为 0（该租户 2026 年才启用，历史采购未导入）——
   **字段结构可用，业务数值不代表该租户真实经营规模**，上线前在目标租户复测。
8. **distribute 归属**：`distribute/*` 是渠道分账不是库存，放进库存域会做错看板。
9. **方法标注为 `?` 的端点**（约 40%）：`api-endpoints.json` 中 `methods` 为空或 `?`，需先用 OPTIONS/试探确定 GET/POST 再接。
