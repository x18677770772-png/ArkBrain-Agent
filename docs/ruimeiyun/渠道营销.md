> 依据：睿美云客户端 4.128.8 前端 bundle 静态提取（4229 条接口）+ 508 个只读接口实测（probe-results.json，182 个成功）。
> 租户样本：hospitalKey=bksw9854 / tenantId=1。所有接口路径、字段名均为真实提取值；未经验证处标注「待验证」。

## 一、业务逻辑概述

获客链路（主线）：

```
渠道(市场渠道/服务商/运营媒体/第三方平台)
  → 客户建档(来源 sourcePathName = 一级/二级/三级来源路径)
  → 线索(消费线索 consumptionclue + 项目圈/种草标记)
  → 报备(preparation 报备人) → 邀约/到院(初诊到院 firstComeNum / 复诊 secondComeNum / 老客 thirdComeNum)
  → 开单成交(billing, 开单来源 billingSourceConfigName)
  → 业绩归因(报备人/渠道/服务商 → 渠道结算 channelSettlement / 渠道人员分账)
```

- **渠道域**是整个获客侧的地基：`市场渠道（marketChannel）`承载客户来源树与提成配置；`服务商（serviceProvider/供应商）`是其下的合作机构实体，有独立的签约、回访、结算信息；`运营媒体（onlineChannel，路径前缀 /v1/channelweb/*）`承载线上付费媒体（注册日期、付费金额/付费说明、审批）。
- **来源归因**：客户档案维护「客户第一来源/第二来源/第三来源」三级来源（`addCustomer.baseInfo.key3/4/5`），组合成来源路径（如实测 `市场渠道/公司/公司业绩`）。渠道结算侧对应配置 `oneSourceDiscount / secondSourceDiscount / thirdSourceDiscount`（来源折扣比例）。
- **业绩与提成**：渠道成交产生「推荐成交记录」，走 结算(划扣/项目) → 结算申请 → 审批 → 结算记录/作废 的闭环；分账比例受 `渠道人员分账（subAccount，/v1/distribute/*）` 与 `渠道分成人员（channelDistributeMember）` 双层配置。
- **营销域**：多形态促销（`活动 variousActivities`：满减/一口价/赠品 + 审批 + 定金保留；`抽奖 lotteryActivity`；`海报 poster` 推广统计；`文案 copyWriting`；`卡券`）。活动数据可投放到 商城/积分商城/小程序/公众号（卡券来源枚举 from.1~from.9）。
- **私域域（SCRM）**：小程序会员端（自定义模板 customized-templates、卡券、积分、商城），配合 企业微信(qyWechat) 员工侧触达（群发、会话存档、敏感词、标签）。
- **第三方平台**：美团(团购/预约)、有赞/有赞美业、微盟/weiMo、小红书、烁熵(soYang)、Live800、七陌(qimo)、tpos(探马/智齿/至昧/纵南) 等，统一模式 = 数据配置(find/setXxxDataConfig) + 商品映射(bind/unBindPlatformCommodity) + 客户绑定(relation/unSync) + 订单同步/核销(writeOff/sureOrder)。

## 三、业务流程与状态机

### 3.1 渠道分层与归属

1. 建渠道：`/v1/channel/add3`（市场渠道）或 `/v1/channel/addSupplier`（服务商）；进 `initChannelConfigModel` 取结算配置模板 → `saveOrUpdateChannelSettlementModel` 保存提成配置（收款账户+来源折扣+提成链）。
2. 审批：`/v1/channel/approval`（审批动作）+ `getApprovalStatus`；审批流枚举 `草稿→待审批→审批中→已通过/已拒绝`（`channel:key75~79`），「审批后生效 key104 / 可立即生效 key105 / 需要审批 key106」。集团下发渠道 `不可编辑下发`（`btnDisabledKeys.offlineChannelDelDis.reason`）；中台配置属性（`newOfflineChannel.key42 中台配置的属性`、`当前配置为 key45`）不可编辑/删除。
3. 维护人/分账人：`batchUpdateChannelMaintain` 批量改维护人（`修改维护人 components.key13 / 修改开发人 key14`）；`/v1/channelDistributeMember/getListByChannelId?channelId=` 读分账人，`addOrUpdate` 新增/编辑（PENDING 待激活），`enableMember/disableMember` 启停（启用校验：分成比例之和 ≤90%），`deleteMember` 删除，`approve`（审批，`MarketChannelSubAccount` 审批类型映射），`cancelApply` 撤销。
4. 渠道回访：`/v1/channelVisit/add|update|page|info|invalid|delete`；回访字段 `计划回访人 visitByName / 计划回访时间 planDate / 计划回访内容 planContent / 实际回访人 visitTrueByName / 回访时间 visitDate / 回访结果 visitContent / 回访方式 visitMannerName（电话|微信|现场|其他）`（代码 dataIndex 实证）；状态 `待回访/已回访/离职`；规则「回访日期不能重复 key256」。
5. 变更同步：改渠道名后需 `syncCustomer`（刷新客户档案，「该操作将会使客户档案/相关报表的客户数据/名称进行同步展示」`newOfflineChannel.key25~27`）；`同步到下级 key20`（集团→门店）。

### 3.2 客户来源归因规则

1. 建档时选「客户第一来源/第二来源/第三来源」（值=渠道树节点，路径拼成 `sourcePathName` 如 `市场渠道/公司/公司业绩`）；批量改来源 `/v2/customer/batch/updateSourceType`、改渠道负责人 `/v2/customer/batch/update-channel-directors`、单改 `/v2/customer/single-update-channel-directors`、`/v1/customer/selectionByChannelId`。
2. 开单选「开单来源」（`billing/getCanBillChannelV2`、`billingSourceEpoch/getCanBillChannelV3`、`billing/getChannelTypeTree`；渠道需 `是否启用为开单来源`；禁用语义 `k2 = 勾选后，开单时选择客户成交来源，该{{marketChannel}}不可被查询和选择`）。
3. 提成计算：开单来源命中渠道 → 按 `本市场渠道提成` 配置计算 `项目佣金`；客户多渠道来源时按来源序号命中 `oneSourceDiscount/secondSourceDiscount/thirdSourceDiscount` 折扣比例（×项目提成）；父子渠道按 `parentFirstFlag/parentSecondFlag` 双向勾选才计提（`channel:key127~129`）；提成次数受 `限制可获提成次数` 约束。
4. 到院统计维度：`firstComeNum 初诊到院 / secondComeNum 复诊到院 / thirdComeNum 老客到院`；渠道客户统计 `customerStatistics`、`channel/getCustomerNumber`（实测返回裸数字 3428）。
5. 报备人（preparation）与渠道开发人并存：报表列 `报备人 preUserName`、`目标报备人 preparationTargetName`、`渠道开发人 channelUserId/channelMaintainUserName`、`市场渠道负责人 channelLeader`；接待/回访可 `同步更新接待记录内的报备人 updateRecept`。

### 3.3 渠道结算流（划扣/项目）

```
成交开单 → 生成待结算数据（dealPage / page）→ 刷新客户关系 synChannelDealRecord(ByIds)
→ 勾选订单 → 结算申请 sub/apply（部分结算/全部结算；草稿/非草稿；审批中不可编辑）
→ 审批 approval（通过/拒绝，拒绝需意见）
→ 结算记录 pageClear/clear（结算金额、扣除成本、实际结算佣金、结算凭证、交易流水）
→ 可 resetDeductClear 重置 / deleteClear 删除 / 作废（record.status===3 后不可编辑/作废）
```

- 划扣类项目（次卡/疗程）走 `划扣结算`（`划扣时间/划扣人/划扣次数/剩余划扣次数`），`结算中(划扣)` 状态；「该{{marketChannel}}对划扣项目进行结算，结算申请包含未划扣项目，确认继续提交？」（`marketChannel/marketChannelInfo/checkMarketChannel` 确认弹窗）。
- 「所有待结算的成交将按最新的关系和结算配置重新生成」（`channel:key61~62`）——synChannelDealRecord 会重算。
- 集团视角：`getdealprojectforgroup`、`getapplychilds/getclearchilds`（集团查子门店明细）。

### 3.4 老带新 / 推荐奖励

- 推荐记录（渠道推荐人带来新客）：add → （到院/成交回填，updateCustomer）→ 成交生成推荐成交记录；`是否有效 updateEnableFlag` 可标记无效；「确定标记该推荐记录为无效 key29」「确定删除该推荐记录吗 key30」。
- 推荐成交结算：`addTemp 暂存 → check 校验 → sub 提交 → apply 结算申请 → pageApply 审批列表 → 审批 → pageClear 结算记录`；`clear`（结算动作）+ `getDeductClearList/resetDeductClear`（划扣结算重置）。
- 老带新返利：配置 `门店自动执行 / 集团手动执行`，`仅针对结算核定为缴费的返利`；查询维度：老带新绑定日期/带新日期/新客是否到院/新客是否消费；报表 `oldAndNew 老带新人数排行/老带新金额排行`。

### 3.5 活动与抽奖状态机

- 活动：新建（可存草稿）→ 提交审批（`activityApproval`；`approvalSetting` 配置是否强制审批）→ `待审批→审批中→已通过/已拒绝` → 生效期内 `未开始→进行中→已过期`；`disable` 启停（`updateDisable`）；删除前 `确定要删除该活动？`；库存、可参与次数、限购在开单时校验。
- 定金保留：开单只付定金 → 订单保留至活动结束后 `活动保留时长` 天 → 超时不可支付走退定金流程（`key44` 文案）。
- 抽奖：`addOrUpdate` 建活动 → 客户参与（可分享提高中奖概率）→ 中奖 → `exchange` 兑换 → `getExchangeRecordList/Statistics` 统计 → `generatePoster` 生成分享海报 → `getNewCustomerParticipantList` 新客名单。
- 海报推广：`poster/add|update`（标题≤15字、图 3:4）→ 生效（未生效/生效中/已失效）→ 客户扫码授权手机号/建档 → `posterCount/count` 推广客户数（去重、仅统计建档或授权手机号新建档）→ `detail` 推广统计明细。
- 卡券发放链：定义 card → 上架 cardPut → 发放 cardGiveOut（sendCard）/投放（商城/积分商城/小程序/公众号 from.*）→ 客户领取 → 核销 writeOff / 作废 delete / 过期失效（status 2~9）。

## 五、Agent 可实现的运营场景

以下场景均由上表接口组合即可实现（全部为可确认的只读路径；写操作按第六节约束执行）：

1. **渠道 ROI 粗算**：`/v1/channelweb/page`（运营媒体投入：付费金额/付费时间/付费说明）+ `/report/v1/wym/marketingStatistics/listChannelPerformanceRank`（渠道业绩）+ `listChannelAddCusAnalysis`（新增客户）→ 计算单渠道 业绩/投入、客户/投入；流失预警用 `listChannelCusLossTrend` + `getChannelCusLossConfig`。
2. **本周各渠道到院人数**：`/v1/channel/getAllChannel` 取渠道清单 → `/report/v1/channel/newCustomerChannelAchievement`（新客渠道业绩，含初诊/复诊/老客到院维度字段 firstComeNum/secondComeNum/thirdComeNum 所在报表域）按时间过滤；或 `listChannelNewAndOldCusAnalysis`。
3. **推荐成交排行榜**：`/v1/recommendDealRecord/dealPage`（按结算人/推荐渠道聚合）+ `getRecommendChannel` 渠道名映射 + `getAllNum` 计数汇总；需要金额口径时用 `dealDetailV2` 的成交金额/扣除成本/实际结算佣金。
4. **渠道结算预警**：`pageApply`（审批中/待审批列表）+ `pageClear`（已结算）+ `getDeductClearList`（划扣待结算）→ 输出「未结算金额 TOP 渠道 / 结算超期」清单；导出走 `exportApply/exportClear/exportDeal`。
5. **服务商维护台账**：`listChannelSupplier` + `/v1/channelVisit/page`（最近回访 visitByName/planDate/visitContent）+ `channel/customerStatistics`（客户数）→ 输出「久未回访/合作中服务商」清单；改维护人走 `batchUpdateChannelMaintain`。
6. **老带新效果报告**：`/v1/customer/oldNew` + `revenueCostReport` 域的 老带新人数排行 oldAndNew 字段 + `key843/key840` 维度（新客是否到院/消费）→ 老带新转化漏斗。
7. **活动 ROI 跟踪**：`/v1/activity/page`（活动清单+activityNumber）→ `/v1/market/statistics/customerRecord|cardRecord|userRecord|cardDetailList`（客户/卡券/员工维度的活动统计，实测 10001，返回 `{records,statisticsObj,total}`）→ 核销/兑换数据（`lotteryActivity/getExchangeRecordStatistics`）。
8. **卡券库存与核销日报**：`/v1/scrm/card/list`（applyProjectType/适用项目）→ `cardGiveOutDetail/sendStatistics`、`countType`、`writeOff` 明细 → 输出发放/核销/过期对照（status 2~9）。
9. **种草计划督办**：`/v1/consumptionclue/getgrassgrowingplanlist`、`getgrassplanlist` + `/v1/grass/grass-plan-statistics` → 「今日计划种草人/未发送素材/待反馈」提醒；素材库配套 `/v1/source-material/get-source-material-list`、话术 `get-catch-phrase-list`。
10. **私域客户运营**：`/v1/scrm/customer/scrmCustomerList`（未登录 unLoginCusCount）→ `/v1/qyWechat/message/pre/queryQyInCustomerList`（企微会话对象）→ 群发（`/v1/wechatMassRelation/*`，需配 messageUser）→ 效果回收看 `scoreRecord`。
11. **平台对账**：美团 `getTuanGouProductList/getSecondaryCardList/getPackageList` + `writeOffRecord`；有赞美业 `getMeiYeOrderList` + `getBuckleRecordList`；微盟 `getWeiMoOrderList` + `statisticsWeiMoOrderData`；输出「平台订单↔映射状态（associationStatus 未映射告警）↔系统开单」差异表。
12. **小红书线索跟进**：`/v1/redbook/getredcustomerlist`（新线索：昵称/电话/是否留资/笔记链接/广告计划）+ `getcusbyphone` 查重 → `bindcustomer` 绑定建档 → 未处理线索提醒。

## 六、二开注意事项与坑

1. **鉴权与信封**：`Authorization: <裸JWT>`（无 Bearer）+ `lang: zh-CN`；成功码 10000/10001/10002（10002=数据为空也走 success 分支）；`X-No-Wrap: true` 可拿原始数据（如 getCustomerNumber 直返数字）。**20002 有多重含义**：真实「method not supported」（msg 带 `Request method 'POST' not supported`）、未开通增值功能（「请联系睿美云销售进行咨询开通」）、参数缺失（「商品OR项目OR套餐？」）。判断可用性必须看 msg 而非只看 code。
2. **分页两套**：渠道域新接口多用 `{current,size}`（微盟/美团/weiMo 实测），旧接口用 `{page,limit}`；混用报 20002。POST 不支持时降级 GET 再试（probe 中 allMaintainers/getDealPro/findMeiTuanDataConfig 等均如此）。
3. **空值序列化**：空值常是字符串 `"null"`/`"[]"`；`contact:null` 与 `contact:"null"` 并存；数值可能带引号。判空一律按「falsy 字符串」处理。
4. **字段双轨**：同一数据在列表里可能是 `xxx` 与 `xxxDeserialized`（如 `applyCustomerTypes` / `applyCustomerTypesDeserialized`）双字段，一个 JSON 字符串一个数组；嵌套对象常被字符串化（`expertInfos` vs `expertInfo`）。
5. **审批与集团下发**：渠道/活动/分账人变更多数要过审批（`待审批→审批中→已通过/已拒绝`）；「集团下发的不能编辑」「中台配置的属性不可编辑/删除」——写操作前先查 `getApprovalStatus`、`IS_TOP_GROUP` 上下文，避免无效写。
6. **写后同步**：改渠道名/维护人后必须 `syncCustomer` 刷新客户档案（文案明示会影响客户档案与报表展示）；推荐成交关系变化用 `synChannelDealRecord(ByIds)` 重算（「所有待结算的成交将按最新的关系和结算配置重新生成」）。这两步是异步的，UI 用轮询提示「数据处理中」，二开需自行轮询。
7. **渠道结算 90% 红线**：分账人启用前校验「结算比例之和已超过90%不可支持启用」（前端硬校验，后端待验证）；来源折扣为 0~100 整数百分比；`parentFirstFlag/parentSecondFlag` 与父级 `子一级/子二级提成` 是双向勾选逻辑，漏勾则不计提（channel:key127~129）。
8. **第三方授权生命周期**：平台功能未开通时 `getAuthorizationUrl` 直接 20002（销售开通闸门）；授权、token 有效期、回调地址均由后端托管（前端只见 `authorizationStatus` 与 `findXxxDataConfig`），二开时不要假设能拿到平台 token；`delYouZanAppId`/`setYouZanAppId` 是租户级开关。
9. **同步是异步任务**：企微部门/员工同步走 `synch` → `synchStatus` 轮询；商品映射 `dealProductForPlatformBatch` 为批量任务；`syncClick` 触发全量同步。任务失败只在前端 toast，需查 `synchStatus`/`findXxxDataConfig` 判断。
10. **映射完整性**：平台商品 `associationStatus=0 未映射` 时订单/核销数据无法自动关联到系统项目；对账场景必须先监控未映射清单（`getPackageList` 等直接给出该字段）。
11. **POST-only 的 GET 接口**：channelweb 系（page/detail/add/pay）在 bundle 里全走 GET 封装，但 probe 显示部分 POST 才被支持——先按 bundle 方法尝试，20002 且 msg 含 "not supported" 时换方法重试。
12. **敏感数据边界**：企微会话存档（msgList/roomMsgList）与敏感词统计涉及员工聊天记录；探马(tanma) 返回企微客户明文（externalUserId/qwCustomerId），二开需注意权限隔离（`渠道用户配置 channelUserConfig` 是现成的按人授权模型）。
13. **报表域独立鉴权**：营销分析报表在 `/report/**` 前缀下（非 /v1），且大量接口为 `{page,limit}` + 时间区间的 POST；`/report/v1/channel/exportUtil` 是通用导出器（多报表共用，参数带报表类型）。
14. **待验证清单**：channelweb 系写接口的准确方法；`/v1/channelPersonnel` 独立后缀（本次仅见 `channelDistributeMember` 与 `/v1/distribute/*` 两套，channelPersonnel 疑为纯前端命名空间）；`/v1/market/active/*` 与 `/v1/activity/*` 的关系（前者疑似旧版市场活动）；卡券状态 status.1 的具体文案（i18n 缺失）。
